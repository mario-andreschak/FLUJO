# Find an MCP connection

Try **Find bundled options** even before adding a model account. A matching standard bundled server is discovered directly from this workspace and opens configuration without contacting a model or public discovery source. Wider AI-assisted research uses one explicitly selected text-model call to interpret the request; ranking, cost evidence and install plans come from actual configured or Registry metadata.

Start with the capability you need, such as “search the web”, “work with local files” or “edit a spreadsheet”. Marketplace searches only when you submit the request. It expands common capability words into a bounded set of Registry name queries and checks names, titles and descriptions for relevance. Spaces and dashes do not require knowing an exact package name. Exact Registry names still work, and installed-card icon lookups keep their direct path.

Search covers bounded matching pages, rather than a complete semantic index of every Registry entry. Results say when sources were unavailable or pages were truncated. Refine the capability if the result is too broad. Loaded pages form one stable search session; pagination does not repeatedly fetch and rerank the upstream catalog. An expired page cursor requires a new search.

Switching setup tabs preserves Marketplace's draft, committed search, loaded pages, filters, detail selection and completed optional reviews. Hidden controls and dialogs are inactive. Leaving cancels pending requests; returning does not automatically spend model tokens or restart a review. Closing setup or switching workspaces starts a fresh session.

AI-assisted discovery requires an explicitly selected saved text-model connection. It prefers relevant FLUJO selections, then reviewed local options when genuine review evidence exists, then hosted options; unreviewed local packages are identified separately. There is currently no durable repository trust-rating store, so Registry lifecycle status, stars and execution permission do not create a “reviewed local” claim. Exact supported identities and capabilities are checked independently of the most popular Registry page, including existing bundled servers.

Within each group, evidenced free capabilities precede bring-your-own-key, paid and unconfirmed pricing. A required secret API-key declaration can establish BYOK setup, but provider fees remain unconfirmed. OAuth, keyless endpoints and open-source connector code do not prove that service usage is free. The free classification for bundled local core operations excludes model inference, connected services and infrastructure. Unsupported pricing stays unknown; model prose cannot change ranking or invent price and trust evidence.

An existing bundled server opens **Configure existing server**. Discovery does not enable it, execute a tool or reinstall it. A disabled same-name server cannot be reported as already connected. New installations still show the exact current command or endpoint and require approval; changed Registry plans are refused. Recommendation category and optional static/model risk assessment never grant trust or execution consent.

Research uses bounded, tool-free text requests through the saved provider: no agent/CLI, fallback or media route, retries, redirects or built-in tools. Each model call has a token cap and cancellation deadline; the overall research request also has a deadline. Browser cancellation propagates to the provider and Registry calls. Shared read-only Marketplace acquisition can finish for another caller within its own bound. Discovery does not evaluate arbitrary candidate code or certify safety.

Local acceptance uses rendered modal lifecycle tests and `node scripts/smoke-mcp-discovery.mjs` against the production build, public Registry and a deterministic local model. This proves transport, recommendation policy, cancellation and unchanged configuration/consent; it does not establish real-model judgment accuracy or universal search recall.
