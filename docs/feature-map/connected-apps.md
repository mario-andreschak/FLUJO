# Connected Apps

Routes: `/mcp`, `/mcp?server=<name>`

Here the user gives agents extra abilities by connecting apps (MCP tool servers): files, services, web tools and so on. A guided "Connect App" wizard helps pick a ready-made app, search the public marketplace, or connect one from a URL, a GitHub repository or a command on this computer; an AI-assisted option can research and install one for you. Each connected app shows as a card with its status. Opening a card lets the user look at and test its tools, resources, prompts and skills, and edit its environment variables. Apps can be enabled, disabled, restarted, edited, deleted, imported and exported. A basic agent does not need any connected app.

## Sub-features

- `connected-apps-list`: server cards with status (Connected, Disconnected, Error), "Search servers…", "Group cards" and "Sort servers".
- `connected-apps-connect-wizard`: "Connect App" opens "Let’s connect an app" with "AI-assisted" (Recommended), "Help me choose", "I have connection details" and "I’m an expert".
- `connected-apps-setup-dialog`: the full server setup with tabs "Spotlight", "Marketplace", "GitHub", "Configure & Test", "Remote", "Reference servers".
- `connected-apps-details`: the app's name on its card is a button (for example "Open filesystem"); it, or a click on the card, opens the details with tabs "Tools", "Resources", "Prompts", "Skills", "Environment Variables"; tools can be tested here. "Save changes" on "Environment Variables" restarts the app with the new values before it returns, so a tool test right after it uses them.
- `connected-apps-card-actions`: "Edit server", "Delete server", "Restart server", "Retry connection", "Expose to external apps", favourite star, move to folder, and sign-in ("Authenticate with <server>") for apps that need it. With sign-in for several people on, also "Copy to a team workspace: <name>".
- `connected-apps-delete-in-use`: "Delete server" on an app that is still used opens "Delete “<name>”?". It lists each place: an agent ("Agent with <n> steps that use this app", with "<Persona>’s own copy of an agent" when it is a Persona's own copy), a Persona ("Persona, Connected App") and an automation ("Automation that checks this app on a schedule" or "Automation that waits for this app’s events"). Each place has a "Switch to" choice: another app, or "Leave the steps without an app for now", "Take the app away from <Persona>" or "Turn the automation off". A Persona is only offered apps that are switched on. Choosing to take the app away shows "<names> will stop using this app. …". "Delete app" stays off until every place has a choice; "Cancel" keeps everything. An app nobody uses is deleted at once, as before.
- `connected-apps-shared-editing`: with sign-in for several people on, "Edit server" says "<name> is editing this too…" and offers "Who changed what" (with "Restore this version"; a restore never changes stored secrets). The editor closes when it saves, so a save after someone else's opens "Someone else saved first" on the page ("Compare", "Load their version", "Save mine anyway").
- `connected-apps-bulk`: "Select", then "Select all" and enable or disable several servers at once.
- `connected-apps-import-export`: "Import" and "Export" menus, each offering several config formats ("<name> format").
- `connected-apps-bundle-install`: drop an MCP bundle file (`.mcpb`, or the older `.dxt`) anywhere on the page ("Drop the .mcpb file to install it"), or choose "Import" → "MCP bundle file (.mcpb)…". The dialog "Install an MCP bundle" (or "Update <name>" when that bundle is installed) shows the name, author, "What it will run", "Trust", "Works on", "Tools it lists", "Name in FLUJO" and "Settings". "Trust" shows one of three signature states: "Signed and checked" (who signed it and which authority vouches for them), "Signature not valid" (the reason; "Install" is off) or "Not signed" (a note; installing is allowed). Secret settings are password fields; folder and file settings have a "Choose folder"/"Choose file" button that opens FLUJO's folder browser, and typing the path still works. "Install" refuses a folder or file that does not exist, is the wrong kind, or lies in FLUJO's own key folder. Nothing is unpacked or started before "Install"/"Update". The bundle goes to `mcp-servers/mcpb/<name>` in the workspace; deleting the server deletes that folder.
- `connected-apps-apps-dashboard`: "MCP Apps Dashboard" button (accessible name "Open MCP Apps Dashboard").
- `connected-apps-client-features`: each card's switches "Render interactive apps" and "MCP Skills" are on unless turned off; "Edit server" → "Allow this tool to ask you questions" (elicitation: forms and links) is on too. Apps run in an isolated or host-trusted setup keep these off until switched on.
- `connected-apps-journey`: first-run guide "Your first AI + app agent" with "Inspect and test tools", "Open simple builder" (straight into the simple builder) and "Hide this guide".

## How to get to it (user POV)

- Choose "Connected Apps" in the top navigation (`data-tour="nav-mcp"`).
- Choose the "Connected Apps" link on the home page's "Connected Apps are optional" card.
- Open `http://127.0.0.1:<port>/mcp`; add `?server=<name>` to open one server's details directly.

## Driving it with flujo-drive

Preconditions: a throwaway instance from the verify-flujo skill. Testing a real tool needs a connected, enabled app; looking at the page and the wizard does not.

- **Open the page**: `node scripts/flujo-drive.mjs open /mcp` → heading "MCP servers", the toolbar and, on a fresh instance, the four built-in apps bash, browser, filesystem and flujo ("4 of 4 servers").
- **Open the wizard**: `node scripts/flujo-drive.mjs click /mcp --role button --name "Connect App" --then-shot apps-wizard.png` → "Let’s connect an app" with four choices.
- **Reach a setup path**: use `steps /mcp --file <steps.json>`: click button "Connect App", click "I have connection details", then `aria` → "Where does the app run?" with "At a remote URL", "In a GitHub repository", "On this computer".
- **Inspect a server**: `node scripts/flujo-drive.mjs aria "/mcp?server=<name>"` → the details dialog with its tabs.
- **Install a bundle**: `node scripts/flujo-drive.mjs steps /mcp --file docs/feature-map/steps/connected-apps-bundle-install.json` drops `__tests__/mcp/fixtures/mcpb-signed/hello-signed-by-mcpb-2.1.2.mcpb` on the page → "Install an MCP bundle" with "Hello Bundle", "by FLUJO tests", "What it will run" `node <bundle folder>/server/index.js`, "Not signed" (its signer is not vouched for here), "hello — Say hello", "Greeting" filled with "Hello" and an empty password field "Token". It picks the home folder with "Choose folder: Notes folder" → "Select this folder", types a folder that does not exist and clicks "Install" → `Check "Notes folder": "…" does not exist on this computer or cannot be opened.`; picks a real folder again and installs → "hello-bundle is installed and starting.", a "hello-bundle" card that shows "Connected" and whose tool `hello` answers "Hello, world!". Dropping the file again opens "Update hello-bundle" with "Leave empty to keep the saved value."; it closes that, deletes the card, and the bundle folder `mcp-servers/mcpb/hello-bundle` is gone from the workspace.
- **Check a signed bundle** (needs a FLUJO launched with `NODE_EXTRA_CA_CERTS=__tests__/mcp/fixtures/mcpb-signed/test-root-ca.pem`; `npm run journey:feature-steps` sets this up): `node scripts/flujo-drive.mjs steps /mcp --file docs/feature-map/steps/connected-apps-bundle-signed.json` drops the same file → "Signed and checked" and "Signed by Ada Example (Example Tools)." with "FLUJO Test Signing CA vouches for the signer". On a FLUJO launched without that variable the same file shows "Not signed" (see "Install a bundle").
- **Refuse a changed bundle**: `node scripts/flujo-drive.mjs steps /mcp --file docs/feature-map/steps/connected-apps-bundle-changed.json` drops `__tests__/mcp/fixtures/mcpb-signed/hello-changed-after-signing.mcpb` → "Signature not valid" and "The file was changed after it was signed. FLUJO will not install this bundle."; the "Install" button is off.
- **Ask before deleting an app an agent uses**: `node scripts/flujo-drive.mjs steps /mcp --file docs/feature-map/steps/connected-apps-delete-in-use-cancel.json` clicks "Delete server" on the `bash` card, which the built-in "FLUJO" agent uses → dialog "Delete “bash”?" with the group "FLUJO: Agent with 1 step that uses this app". "Delete app" is off until "Switch to" has a choice (`filesystem`, or "Leave the steps without an app for now", which adds "FLUJO will stop using this app. …"). "Cancel" keeps the `bash` card, still "Connected".
- **Delete an app agents use** (needs a local app "notes-app" next to "notes-app-2" and two agents, "Notes helper" and "Notes reader", whose steps use it; `npm run journey:feature-steps` sets this up): `node scripts/flujo-drive.mjs steps /mcp --file docs/feature-map/steps/connected-apps-delete-in-use.json` clicks "Delete server" on "notes-app" → dialog "Delete “notes-app”?" with the groups "Notes helper: Agent with 1 step that uses this app" and "Notes reader: …". It switches "Notes helper" to `notes-app-2` and leaves "Notes reader" without an app ("Notes reader will stop using this app. …"), then "Delete app" → the card is gone, "Notes helper"'s step uses `notes-app-2` and "Notes reader"'s step has no app. With a Persona that uses the app under "Apps", the dialog also lists "<Persona>: Persona, Connected App"; choosing another app moves the Persona's tool choices to it.
- **Proof**: an ARIA snapshot and a screenshot of the server list, the wizard, or a server's details.

## Gotchas

- The navigation says "Connected Apps", but the page heading is "MCP servers" (small label above it: "Connect").
- With the "Legacy" look (Settings → Appearance), the main button reads "Add server" and opens the setup dialog straight away instead of the wizard.
- Each driver command is a fresh browser session; dialogs do not survive between commands. Use `steps` or the `?server=` link.
- While no app is connected, the first-run guide shows a second "Connect App" button; both open the same wizard.
- Clicking a disabled server's card does nothing and its name button is off; enable it first.
- Clicking the middle of a card can land on its switches, which do not open the details; the name button always does.
- "Connected" only means the server started. A tool works only after a real tool test succeeds.
- When "3) Test run" of a command on this computer fails because a Python script or package, or a Node.js file or package, is missing, the red message names that cause and the fix (for example "Python could not find the script …"). Other failures show "Connection test failed. See the console for details." The server's own error is always in the console. See `docs/features/mcp/local-servers.md`.
- Installing apps from GitHub, the marketplace or AI-assisted setup downloads and runs third-party code on the machine. Do not do that in an unattended run.
- The search box has only a placeholder, so `fill --label` will not find it.
- A bundle file larger than the upload limit (about 99 MB, less on computers with under 3 GB of memory) is refused with its size and the limit. A bundle signature counts as "Signed and checked" only when it leads to an authority in the operating system's certificate store (or in Node's `NODE_EXTRA_CA_CERTS` file); a sound signature from any other certificate shows "Not signed" with the name it claims. FLUJO does not look up withdrawn certificates online.
- Installing a bundle is refused for people without host access in multi-user mode, and in protected setups that allow only reviewed, preinstalled servers.
- The main button carries `data-tour="add-mcp-server"`; the "Marketplace" tab carries `data-tour="mcp-marketplace-tab"`.
- Deleting an app that is still used changes the agents, Personas and automations first and deletes the app last. If it stops part-way, the app stays in the list and the places already switched stay switched; deleting again lists only what is left. Changing an automation that runs a Persona works only from this computer, like the Persona pages. Turned-off automations are not listed: their editor asks for another app when theirs is gone. Old data that still names a deleted app no longer breaks a Persona's Flows area; it shows "Connected App “<name>” no longer exists …" instead.
- "Copy to a team workspace: <name>" appears only while sign-in for several people is on (Settings → "Users and sign-in"). Its dialog lists only workspaces the person may change; keys, passwords and sign-ins stay behind and the result lists what to enter in the team workspace. A copied app starts turned off.
