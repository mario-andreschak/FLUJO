# Codex runtime and ordinary session qualification

This is the runtime/session batch of issue [#1097](https://github.com/mario-andreschak/FLUJO/issues/1097), based on main `d3e5c64ec52f08de16c221140d99d7ea788d80c5`.

Allowance, discovery and ordinary inference select the same leased executable.
Runtime receipts bind the CLI version/digest to the installed SDK and admitted
protocol/qualification contracts. Update probes cover bounded pagination,
received error framing and the SDK's public start/resume argument vectors. They
create no inference or tool turn and do not claim account entitlement.

Ordinary subscription conversations use separately owned app-server stdio.
Flow instructions retain developer authority; deltas preserve message identity;
the final answer is distinct from commentary. Steering targets the active turn
and acknowledges only acceptance. Uncertain submissions do not automatically
start a replacement turn or return a possibly accepted correction to the inbox.
Process birth admission, default rejection of server requests, and confirmed
closure remain required. Native Original/private and API-key SDK routes retain
their existing admission and execution policy.

Session compatibility now includes account/runtime/instruction/tool/configuration
identity and canonical history. Protocol totals persisted with session metadata
prevent counting earlier turns again after a registry reset. Latest-context,
cached input and reasoning output remain separate from accumulated usage.

## Local and real-runtime evidence

- Local typecheck and whole-source lint passed on the candidate application source.
- The inspected non-container application build passed under the shared build
  lease, including all five MCP workspaces, Next webpack, production TypeScript
  and route generation. Webpack reported 5.0 minutes; this is a measured phase,
  not an overall elapsed-time estimate.
- Five focused suites cover 121 cases. Unchanged successful inputs were reused;
  the final adapter/RPC run passed 68 cases, the updater retry passed 24, and the
  unchanged allowance/owned-transport suites passed in the original focused run.
- Bundled CLI and SDK `0.162.1`, model `gpt-6-luna`, medium reasoning, existing
  file-backed ChatGPT login, on Windows: production adapter and loopback bridge
  called the actual bundled filesystem MCP server once and recorded one
  call/result pair. Final answer and commentary stayed distinct.
- A new CLI child and fresh adapter reused JSON-roundtripped session metadata
  after clearing the registry. The captured request contained only the appended
  input, retained the thread, and counted new usage rather than cumulative history.
- Real steering during visible output produced one acknowledgement, no requeue,
  and no replacement turn. Cancellation after a visible delta retained partial
  transcript text and dispatched no replacement turn. Expanded live acceptance
  passed in 29.464 seconds; checks ran concurrently, so timings are not summed.
- One live retry hit the existing Windows process-birth admission refusal.
  Subsequent focused acceptance passed without weakening that boundary.

The sanitized runtime receipt identifies CLI/SDK/protocol and reported token
subsets; dollar cost was not reported. Private machine logs and credentials are
not committed. Full/remote CI, container/image, installed release and broader
acceptance suites were not dispatched under the existing development pause.
