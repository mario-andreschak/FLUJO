# Agents

Routes: `/flows`

Here a user builds and manages AI agents (called "flows" inside the app). The list page, titled "My agents", shows every saved agent as a card that can be searched, sorted, grouped, starred, copied, moved into a folder, deleted, or opened in chat. A new agent can be described in plain words ("Create with AI"), built step by step in the simple Easy view ("Start simple"), or wired by hand on the node canvas in Expert view ("Start expert"). In the editor the user names the agent, adds steps, edits each step's settings, saves, and tries it.

## Sub-features

- `agents-list`: the "My agents" list with agent cards, or "No agents yet" with "Create my first agent" when there are none.
- `agents-search-sort`: the "Search agents…" box, plus "Group agents", "Sort agents", "Show agent cards" and "Show compact agent list".
- `agents-card-actions`: on each card, "Use" (opens it in Talk), "Edit", "Make a copy", "Move to folder", "Delete agent" and the favorites star. With sign-in for several people on, also "Copy to a team workspace: <name>".
- `agents-delete-in-use`: "Delete agent" on an agent that is still used opens "Delete “<name>”?". It lists each place: a Persona's "Persona, Core Flow" or "Persona, behavior “…”", an automation ("Automation that runs this agent", "…asks this agent whether to run", "…starts after this agent") and other agents ("Agent that calls this one in a step"). Each place has a "Switch to" choice: another agent, or "Remove it and pause <Persona>", "Remove this behavior", "Turn the automation off" or "Empty the step for now". A part a Persona's Role needs only offers other agents. Choosing to pause a Persona shows "<name> will be paused. …". "Delete agent" stays off until every place has a choice; "Cancel" keeps everything. Afterwards the banner says "Agent deleted." or "Agent deleted. Now paused: <names>." An unused agent is deleted at once, as before. Uninstalling a package asks the same questions for its agents (see [Packages](packages.md)).
- `agents-change-models`: "Change models" selects several agents and swaps their AI model in one go (dialog "Quick-change models").
- `agents-create-ai`: "Create with AI" opens the "Create an agent" dialog, where the user describes the agent and picks "AI used to build it".
- `agents-easy-builder`: "Start simple" opens the Easy view. The user fills "Workflow goal", chooses "Create goal step" (then "Add this step"), fills "Agent name" and chooses "Try my agent".
- `agents-expert-canvas`: "Start expert", or the "Expert view" switch, opens the node canvas with a list of node types ("Ask AI", "Send the answer", "Use a connected app", "Ask another agent" and more), "Add node", "Tidy up layout", "Undo" and "Redo".
- `agents-human-step`: a step that waits for a person. In the Easy view, "Add human step" adds one at the end and opens its settings; in Expert view it is "Ask a person" in the node list. The settings dialog "Human step" offers "Approve", "Fill in" and "Review and edit", the question, the wait time and what a no does. "Save" stays off while the question is empty. On the canvas the step has three outgoing handles: "Yes: connect the next step" (bottom), "No: connect where a no should go" (left, red) and "Timed out: connect where a time-out should go" (right, orange). When the flow runs, the chat shows a card with the step's title, "Waiting for you", the question, "Change the text if needed" (Review and edit) or the questions (Fill in), and "Send answer" / "Approve" next to "Turn down" / "Reject"; a wrong answer shows its message under the question, and a saved one shows "Answer saved. The flow goes on." See [Human step](../features/flows/human-step.md).
- `agents-node-properties`: selecting a node fills the "Inspector" panel ("Node name", and "Full settings" for every option). With nothing selected, the panel shows "Flow details" with "Flow name".
- `agents-system-prompt`: in Expert view, an AI step's "Full settings" → tab "Input / output" has "Exclude system prompt" and, while it is off, the group "Parts of FLUJO’s system prompt" with the checkboxes "Basic rules", "Workflow and hand-offs", "Other agents", "Asking people", "FLUJO tools" and "Stored results" (all ticked by default). "Prompt rendering order" lists "FLUJO system prompt" while any part is left in. The "Task" tab's preview shows FLUJO's part under "# GENERAL INFORMATION:". See [What FLUJO tells the AI](../features/flows/system-prompt.md).
- `agents-tool-loading`: in Expert view, an AI step's "Full settings" → tab "Input / output" has two dropdowns. "Tool descriptions" offers "Automatic: names first when there are many tools" (default), "Names first, details when needed" and "All details on every turn". "Code mode" offers "Automatic: on when tool details load when needed" (default), "On" and "Off". A choice other than Automatic is saved with the step. See [Deferred tool descriptions](../features/mcp-scoreboard/deferred-tools.md) and [Code mode](../features/mcp-scoreboard/code-mode.md).
- `agents-tool-result-limit`: in Expert view, an AI step's "Full settings" → tab "Input / output" has the dropdown "Tool result size limit": "Use the workspace setting (Settings → Advanced)" (default), "Automatic (based on the model)", "Custom size" (with "Size limit for this step (KB)", whole kilobytes from 1 to 102,400; "Save changes" stays off and "Enter a whole number of kilobytes from 1 to 102,400." shows otherwise) and "Keep results in full". A choice other than the workspace setting is saved with the step and wins over Settings → Advanced for that step. See [Tool result size limit](../features/tool-result-size-limit.md).
- `agents-save`: the "Save flow" button (it shows the text "Save"). A chip reports "Save status: Saved / Unsaved / Saving…", and a banner says "Agent saved."
- `agents-more-actions`: the "More actions" menu ("Previous versions" or "History", "Duplicate agent", "Delete agent", "Improve with AI", "Improvement and versions").
- `agents-unsaved-guard`: leaving with unsaved edits opens "Unsaved changes" with "Discard changes", "Save changes" and "Cancel".
- `agents-shared-editing`: with sign-in for several people on, the editor says "<name> is editing this too. If they save first, you will be asked what to keep." A save after someone else's opens "Someone else saved first" with "Compare", "Load their version", "Save mine anyway" and "Keep editing". "More actions" → "Who changed what" opens "Who changed this flow" with "View" and "Restore this version".

## How to get to it (user POV)

- Choose `Agents` in the top navigation (`data-tour="nav-flows"`). Below 1536 px wide, first choose `Open navigation menu`.
- Open `http://127.0.0.1:<port>/flows`.
- Choose `Use` / `Edit` from elsewhere, or follow a copied agent link (`/flows?flow=<id>&mode=edit`).
- The setup journey's `/flows?create=assistant` link opens a new Easy-view draft at once.

## Driving it with flujo-drive

Preconditions: a throwaway instance from the verify-flujo skill. A fresh instance has one built-in agent, "FLUJO", and no AI model. Building and saving works without a model, but "Try it", "Try my agent" and "Create with AI" need one. If no model can be connected, report those steps as unmet.

- **List**: open the page. `node scripts/flujo-drive.mjs open /flows` → the heading "My agents" and, on a fresh instance, the built-in "FLUJO" agent card ("1 of 1 agent").
- **Start simple**: `node scripts/flujo-drive.mjs click /flows --role button --name "Start simple" --then-shot agents-easy.png` → the Easy view ("Build it like a simple recipe.") and the banner "Your new agent is ready. Give it a name, add a task, then try it."
- **Build and save** (one session, because a draft is lost between commands): `node scripts/flujo-drive.mjs steps /flows --file agents-save.json`. The steps: click button "Start simple"; fill "Workflow goal"; click button "Create goal step"; fill "Agent name"; click button "Save flow"; expect-text "Agent saved."; then shot and aria.
- **Expert canvas**: `node scripts/flujo-drive.mjs click /flows --role button --name "Start expert" --then-shot agents-expert.png` → the canvas with the node list and "Add node".
- **System prompt parts** (one `steps` session): open the built-in "FLUJO" agent with "Edit"; switch on "Expert view"; select the AI step and click "Full settings"; click tab "Input / output"; expect the group "Parts of FLUJO’s system prompt" with six ticked checkboxes; untick "FLUJO tools"; click "Save changes"; click "Save flow"; expect-text "Agent saved."; reopen "Full settings" → "Input / output" and expect "FLUJO tools" unticked; turn on "Exclude system prompt" and expect the group to disappear. Shot and aria named `agents-system-prompt`.
- **Tool descriptions and code mode** (one `steps` session): open the built-in "FLUJO" agent with "Edit"; switch on "Expert view"; select the AI step and click "Full settings"; click tab "Input / output"; expect the dropdowns "Tool descriptions" and "Code mode", both on their "Automatic" choice; choose "Names first, details when needed" and "On"; click "Save changes"; click "Save flow"; expect-text "Agent saved."; reopen "Full settings" → "Input / output" and expect both choices kept. Shot and aria named `agents-tool-loading`. With an AI model connected, ask the agent something that needs its tools: the executed steps show `search_tools` and `run_tool_script` calls.
- **Tool result size limit of a step** (needs a production build): `npm run check:tool-result-limit` builds "Big log reader" in the simple builder with the local stand-in AI, opens it with "Edit", switches on "Expert view", selects the AI step and clicks "Full settings" → tab "Input / output", sees `0` refused in "Size limit for this step (KB)", chooses "Keep results in full", clicks "Save changes" and "Save flow" ("Agent saved."), reopens the step to see the choice kept, and asks the agent again: the reply now quotes the whole 43 KB result instead of a `flujo://run/` link. Proof named `step-keeps-full` under `tool-result-limit/desktop/` in the evidence folder.
- **Delete an agent a Persona uses** (needs a Persona, so an AI model and a Role first; see [Personas](personas.md)): save two agents, "Research" and "Research v2"; on the Persona's Flows area choose "Change Flow" under "Core Flow" and pick "Research" with "Use this Flow"; back on `/flows` click "Delete agent" on "Research" → dialog "Delete “Research”?" listing the Persona with "Persona, Core Flow". In the group "<Persona>: Persona, Core Flow" open "Switch to" and choose "Research v2", then "Delete agent" → banner "Agent deleted.", the card is gone and the Persona's "Core Flow" shows "Research v2". Repeat with "Remove it and pause <Persona>" → the warning "… will be paused …", banner "Agent deleted. Now paused: <Persona>." and the Persona shows as paused. Shot and aria named `agents-delete-in-use`.
- **Human step journey** (`agents-human-step`, all in one go with its own local stand-in model): `npm run build && npm run journey:human-step` (or `node scripts/human-step-journey/run.mjs --base-url <instance>` on a launched instance). It connects the stand-in model, adds a Human step in the Easy view ("Add human step", "Review and edit", "Save" off while the question is empty, "Save flow", "Agent saved."), adds "Ask a person" on the Expert canvas and fills its settings, runs Draft → Review and edit → Send in the chat (the card shows the draft, the edited text is what the next step sends: "Sent: …"), and answers a Fill-in step at 360 px wide: "This answer is needed.", then "Enter 5 or less.", then a good answer, then the conversation is opened again and asks nothing more. Screenshots, ARIA snapshots and `report.json` land in `human-step-journey/`.
- **Proof**: an ARIA snapshot and a screenshot of the saved agent in the editor (chip "Save status: Saved"), then of `/flows` showing its card.

## Gotchas

- A new agent is only a draft until its first save. Each flujo-drive command is a fresh browser, so an unsaved draft's `?flow=<id>&mode=edit` link shows "Agent not found." Use `steps` for anything after "Start simple" or "Start expert".
- The Save button's accessible name is "Save flow", even though it shows "Save".
- When a model exists, the Easy view first asks "Yes, help me" or "No, I’ll build it myself". The goal field only appears after you answer. Either way, a new AI step gets the favourite (or first) connected AI; "No" only turns off AI help while building.
- "Try it" / "Try my agent" stay disabled until each AI step has a model and the name is not "Untitled agent". Without a model, the Easy view warns "This step still needs an AI…".
- The canvas is the slowest part. The first load in a dev instance compiles it, and nodes have no stable accessible names: drive the node list and the "Inspector", not canvas positions.
- The node list sits beside the canvas only at 900 px wide or more. Below that, use "Add node".
- "Tool result size limit" also exists only in Expert view. "Keep results in full" still moves one result that is more than half of the model's context window, so a run never fails on it.
- "Tool descriptions" and "Code mode" only change steps that use connected apps. On "Automatic" a step with few tools looks exactly as before; the catalog and `run_tool_script` appear once its tool descriptions would fill about 5% of the model's context window. Test with "Names first, details when needed" and "On" to see them on any step.
- The "Input / output" tab and the system prompt parts only exist in Expert view. The Task tab's preview follows the switches at once but reads steps, edges and tools from the saved agent, and it cannot know tools an app only lists once connected.
- A flow with a Human step always runs saved, also when it is started as an MCP tool or inside a sub-flow, so its wait survives a restart. Trying it shows a card in the chat; building and saving it needs no model. A step a sub-flow asks shows its card in the chat of the flow you started.
- The guided tour starts on its own only on the home page `/`, so opening `/flows` directly avoids it.
- The shared-editing parts (`agents-shared-editing`) appear only while sign-in for several people is on; with it off the editor asks nothing new. To see "Someone else saved first", sign in as two people in two browsers, open the same agent in a team workspace and save in both. Their version is never lost: it stays in "Who changed what".
- Deleting an agent that is still used changes the Persona, automation or other agent first and deletes the agent last. If it stops part-way (a Persona busy for more than about 15 seconds, a crash), the agent stays in the list and the places already switched stay switched; deleting again lists only what is left. Changing a Persona works only from this computer, like the Persona pages. A Persona that only keeps its own copy of the agent is listed as "… keeps working" and needs no choice. Turned-off automations are not listed: their editor already asks for another agent when theirs is gone. Every agent is also offered as a tool to MCP clients; deleting it simply removes that tool.
- "Copy to a team workspace: <name>" appears only while sign-in for several people is on (Settings → "Users and sign-in"). Its dialog lists only workspaces the person may change; keys, passwords and sign-ins stay behind and the result lists what to enter in the team workspace. A copied app starts turned off.
