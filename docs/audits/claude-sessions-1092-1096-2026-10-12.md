## Behavior

- `permissionMode: default` is explicit. `PreToolUse` checks the advertised node
  inventory, execution fence, MCP identity and Persona authorization before SDK
  rules can auto-approve. Human decisions remain in `canUseTool`, with one
  decision per tool-use identity and revalidation after delayed approval. A
  handler without a matching authority binding fails; cancellation and terminal
  scope closure fence late callbacks.
- Composed input uses `verbatimPrompts: true`; `/clear`, slash text, `@path` and
  MCP mention syntax are literal content. Tools are supplied in the in-process
  MCP inventory independently of CLI ambient attachments. Actual first-turn
  discovery remains part of authenticated acceptance.
- Stable instructions are recorded explicitly (`snapshot: true`). Context drift
  remains a user update, deduplicated against the latest update; returning to a
  prior value emits the required corrective update. Process nodes may explicitly
  choose `systemPromptPolicy: per-turn` in advanced settings or FlowSpec. That
  policy bypasses the shared freeze and passes a freshly rendered custom prompt
  with `snapshot: false` at the next serialized invocation boundary.
- Resume requires workspace/conversation/node/account isolation, matching tool
  definitions and execution configuration, an unchanged consumed content prefix,
  a compatible accounting checkpoint and an exact native transcript byte/hash
  checkpoint. Missing records, complete-record truncation and same-length edits
  start fresh; transcript verification reads bounded chunks.
  Prompt text may change only under the per-turn policy. The installed SDK and
  bundled runtime versions and message-normalization policy participate in the
  compatibility fingerprint. Main's `native-history-v2` retains complete tool
  payloads when no recovery resource exists; older projections start fresh.
- Metadata contains hashes, identifiers and usage counts, never prompt/history
  content, tool arguments or credentials. Entries expire after 24 hours; at most
  200 recent entries are retained. Missing, incompatible, corrupt, expired or
  pruned state starts a fresh session with canonical history. Previously recorded
  sessions migrate by starting fresh. A new conversation/fork identity starts
  fresh; this batch does not introduce `forkSession` or an in-flight prompt setter.
- Per-key process and file leases prevent concurrent mutation of a session while
  allowing different sessions independently. Cross-process contention waits up
  to 30 seconds, then returns a retryable ownership error. A dead PID permits
  generation-specific stale-lease recovery; a losing recoverer cannot remove
  a new owner's lease. A fully initialized ownership directory is published
  atomically, and contested release preserves a new owner. Unknown/live ownership
  is preserved. The old checkpoint
  is removed before dispatch, so a backend crash cannot certify partially
  consumed history. Only successful final transcript materialization records
  the next checkpoint. Error, cancellation and handoff invalidate reuse.
- Cumulative `modelUsage` and estimated cost are measured against the persisted
  session baseline. Repeated results are deduplicated; cumulative resets preserve
  this invocation's earlier delta. Deduplicated request telemetry covers partial
  work and child agents separately from root context occupancy. Zeroed crash
  placeholders retain observed request usage. Cost metadata
  says `sdk-estimate`, not actual billing; unreleased upstream per-query fields
  are not assumed.
- Outgoing user UUIDs are stable. Result attribution handles merged sends,
  `user_message_uuids`, `result_index` and queued send counts. Durable mailbox
  acknowledgement remains separate from SDK consumption attribution. Active
  background work delays foreground closure; deferred/error terminal reasons and
  unexplained iterator termination are explicit failures, even after an earlier
  successful result. Completion requires settled sends and tools with no SDK
  backlog or background work. All terminal paths
  close the query and cancel late callbacks. Teardown failures report an error
  before the dispatch outcome is saved. Native ownership still requires its
  separate process-exit and stream-close evidence, with a dedicated completion
  notification that the generic outcome callback cannot bypass.
  SDK ambient watchers do not keep a settled foreground turn open; their
  accounting remains partial and the session cannot certify a resume baseline.
- New owned-child identity establishment uses the backend's bounded 3-second
  Windows startup probe with at most three attempts. A measured cold lookup took
  2.244 seconds; the foreign-owner 900 ms probe remains unchanged, including
  concurrent observations. Exhaustion still rejects registration, and an actual
  OS birth identity remains mandatory. This shared helper also covers Codex.
- Redacted lifecycle events record runtime version, compaction, retries, session
  state and estimated accounting. Chat distinguishes compaction, retries and
  pending decisions; the prompt toggle and status wording support all seven
  product languages and phone layout.
